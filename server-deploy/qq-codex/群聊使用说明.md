# 三人群 628128804

2026-11-14 配置，成员：17162047、Codex 1103828665、大肥鱼 2223525305。

## 日常聊天

直接说话，不需要点名或 @。通常一个号先接话，另一位偶尔补一句；说“你们觉得呢”等自然表达时，两位可以各回一句。提到某个号或 @ 时优先由它回应，但不是触发的必要条件。大多数轮次只调用一个模型，最多两次，逐个生成。

第二位能够看到第一位刚才的群回复，因此可以自然接话、吐槽或补充。两号发出的消息本身永远不能开启新轮；只有 17162047 在指定群发来的新消息才有资格开启模型调用。若第二位尚未开始而用户发来新消息，优先处理用户，跳过这句补充。

短时间连发会等待两秒合并，避免一小句就调用一次。两个事件订阅收到同一条消息会去重；同一用户同秒发送完全相同文字／相同提及会被合并处理。

## 上限与暂停

- 每轮最多两次生成；同一个号每轮最多一次，不自动重复失败或不确定是否送达的消息。
- 两号合计最多 6 次／滚动分钟、60 次／滚动小时、300 次／滚动 24 小时，包含失败的已启动调用。达到上限会暂缓，提醒最多每十分钟一次。
- 这是程序发起的模型调用次数上限，不是实际 token 或费用上限。私聊的模型调用独立，不计入这个群额度；Codex 仍使用 ChatGPT 登录额度，Harness 仍使用现有 DeepSeek 配置。
- 计数、暂停和事件去重保存在 SQLite，服务重启不会清零。没有后台自动发起对话或自动续聊任务。
- 说 `暂停群聊`／`先别聊了`：停止接话，清掉等待队列；正在生成的回复完成后丢弃，不继续第二位。已发生的这一次生成仍可能消耗额度。
- 说 `继续群聊`：恢复，暂停期间的消息不补聊。
- `/群状态` 或 `/群帮助`：查看说明，不调用模型。
- `/群清空` 或 `/new`：开始新话题，原始档案与确认记忆保留。

## 记忆与导出

用户明确允许：每个 AI 可使用它自己的私聊确认记忆，并按话题检索自己的私聊旧原文。不会读取另一号私聊档案；两号的私聊原始记录和长期记忆仍分别保存。对外发送的群消息会成为双方可见的群聊记录。

群上下文与原私聊上下文独立；群里不会自动把角色扮演经历或闲聊推测写入私聊长期记忆。可以在 Codex 私聊里管理群长期记忆与档案：

```text
/记住 群 我们喜欢简短的聊天
/查看记忆 群
/忘记 群 M3
/查记录 群 关键词
/导出 群 md
/导出 群 html 2026-11-14
/导出 群 jsonl
```

这些管理命令发给 Codex 的私聊。群里只开放群状态、暂停、恢复和新话题，避免误在群中执行私聊导出。

群档案位于 `/home/ubuntu/qq-group/records/archive.sqlite3`，保存已接收的允许用户文字、两号生成内容及发送状态；不保存图片／语音文件。每日 03:30 加密备份包含群档案、群确认记忆和调度计数数据库；本机 09:30／登录时拉取。原有两个私聊档案备份保持有效。

## 实现与范围

新增 `qq-group.service`，统一管理两个账号的群消息；两个已有的私聊处理器继续只处理私聊，Harness 原 QQ 插件的原生群回复保持关闭，避免重复回复和绕过轮数限制。

Codex 使用既有 CLI；大肥鱼通过独立的 Harness `qq-group` headless profile 复用相同的 DeepSeek 模型配置及本地凭据服务，禁用工具、子代理、自动标题生成等后台模型调用，不启动新的公网端口。群模型只生成文字，发送对象由程序固定为 628128804。

由于用户授权以固定三人群为前提，生成前和发送前会核对成员集合。如果新增成员或无法确认成员，不继续生成／发送。恢复为原三人后，新的用户发言可重新触发。两个 QQ 号任一暂时离线，另一个仍可接收事件并在同一群内回应；需要本人扫码的登录失效仍按原提醒方式处理。
