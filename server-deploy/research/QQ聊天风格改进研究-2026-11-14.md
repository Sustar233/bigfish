# QQ 助手聊天风格研究

研究日期：2026-11-14。只读检查实际提示词、本人私聊的少量最终回复及生成参数，没有修改线上人设、清空会话、发送 QQ 消息或调用付费模型测试。

## 主要结论

优先减少“每句话都要帮用户解决问题”的反应习惯，并让人设在多轮对话中保持一致。单纯缩短回复、堆禁词或增加卖萌词，难以解决当前问题。

这是一份基于小样本的诊断及待验证方案，不能证明某个参数单独造成了 AI 感。

## 已确认的配置与现象

| 项目 | Codex QQ | DeepSeek / Harness QQ |
| --- | --- | --- |
| 闲聊长度规则 | 已要求 1–2 个短句、通常 10–70 字 | 人设文件已要求类似规则，最新请求中确实存在 |
| 实际工作定位 | 文本聊天桥，禁用工具 | standard 预设；系统开头称 coding agent |
| 推理强度 | CLI 参数 low | 最近请求 high |
| 工具 | 已禁用 | 最近请求携带 51 个工具 |
| 人设 | 有独立人设、已确认记忆和历史 | 天然呆人设已加载；约一万字符系统消息还混有工具说明、SkillHub 与服务器规则 |
| 主要样本问题 | 安慰后给建议、主动把闲聊变成小任务 | 角色自我介绍、顺从式“我照做”、默认提供帮助，天然呆和先前强硬说话风格不连贯 |

DeepSeek 的短回复也有明显助手感，例如“那你说吧，你想让我干嘛，我照做就是了”。因此，字数并非充分判断标准。

Harness 当前人设不是没有生效：最新系统消息包含完整天然呆人设与短句规则。框架原有的 coding agent 定位与任务说明仍同时存在。角色不稳定可能还受旧助手回复影响；这是合理推断，尚未用新旧上下文对照实测。

## 建议顺序

### 1. 先给 DeepSeek 做独立的 QQ 闲聊预设

不要直接删除整个 Harness 的工具、权限或工作能力。把 QQ 日常聊天的身份、回复习惯和少量例子集中在独立预设中；用户明确提出实际任务时，再使用办事能力。权限、白名单、审批与事实可靠性继续保留。

闲聊处理应先判断这句话的用意：打招呼、吐槽、调侃、分享，还是明确求助。前四类不自动升级成建议、计划、心理分析或“把任务发给我”。

### 2. 将旧风格从活动上下文中隔离

保留已确认长期记忆和人设文件，在备份后使用新会话比较效果，避免持续让模型模仿旧的客服式、毒舌式或刻意表演式回答。不要把整份旧对话永久塞入记忆。

### 3. 用少量多轮示例定义性格

天然呆表现为偶尔的生活联想、接梗和反应角度，而不是每句话都加食物梗、停顿、口头禅。示例应以普通接话为主，角色表现占少数。

建议风格目标（人工拟写，尚非模型实测结果）：

| 用户的话 | 当前样本里的倾向 | 候选表达方向 |
| --- | --- | --- |
| 困了 | 默认安排吃饭和午睡 | 先接困意，不凭时间推定对方的作息；例如“已经开始靠意志力睁眼了是吧。” |
| 你脑子不行 | “你想让我干嘛，我照做” | 接住调侃，避免退回服务台；例如“刚开口就被你扣光分了。” |
| 帮我上班 | 先讲不能打卡，再推销电脑任务能力 | 在没有明确工作材料时先接玩笑；例如“你是想把班也一块外包了。” |
| 困了，但还要考试 | 马上计算还能睡多久 | 先承接冲突；例如“最烦这种，想睡又不敢睡。”明确询问安排时再给方案 |

这些不是固定回复表，更不能要求每轮都抖机灵。具体表达应沿用上下文，不新增用户没有说过的生活经历。

### 4. 将推理模式作为对照变量

实际 DeepSeek 请求是 deepseek-flash、reasoningEffort=high。可以比较闲聊时关闭思考与当前模式的延迟、模板化、上下文承接和用户偏好；复杂工作仍可启用推理。不能承诺关闭思考必然更自然。

当前使用 Anthropic 兼容接口。DeepSeek 官方文档给出的关闭思考参数是 reasoning.effort=none。需要先确认 Harness 适配器确实能传递这个设置，不能把 low 当成关闭。

思考模式下 temperature、presence_penalty、frequency_penalty 不生效。不能把“把 temperature 调高”当作当前配置的直接解决办法。

来源：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[Anthropic 兼容接口](https://api-docs.deepseek.com/guides/anthropic_api/)。

### 5. Codex 做较小的风格调整

保留当前低推理、无工具聊天设计。重点减少“我帮你……”式的主动任务承接，清理活动历史中重复的安慰模板，用几段与它自身角色相符的正向例子替换抽象禁令。记忆候选提取仍需真实、保守，不能为了聊天自然而编造共同经历。

## 可供试用的核心风格草案

以下只替换聊天风格部分，不能替换权限、身份诚实、工具边界和记忆真实性规则：

> 把对方的话当成聊天的下一句，不默认把它当成求助工单。
> 先接当前这句话的具体意思。吐槽可以接，玩笑可以接；对方没有求建议时，不急着安排他该怎么做。
> 平时像熟悉的 QQ 联系人说话，短句为主，长短自然变化。该解释时讲清楚，不机械限字。
> 少介绍自己的性格，让性格从回应里露出来；大多数话不需要口头禅、动作、食物梗或反问。
> 对方嫌你像 AI 时，不争辩、不索要改进需求清单，直接用接下来的说话方式调整。
> 不凭空推定对方正在上班、几点吃饭或昨晚没睡；只有明确上下文支持时才接这些细节。
> 正事认真办，闲聊不用每轮证明自己有用。不要伪造真人身份或线下经历。

## 验证办法

用同一组约 12 段多轮场景比较：问候、重复“嗯”、疲惫、调侃、改口、临时换话题、拒绝建议、正事求助等。分别评估是否主动给无请求建议、复述、机械反问、角色标签堆叠、忽视上一句，以及实际任务是否仍可靠。

先固定模型和推理模式，仅改预设与上下文；再单独对比推理模式。避免同时换模型、调温、重写人设和加分段发送，否则难以归因。让用户盲选更愿意继续聊的一版，长度统计只作辅助。

目前没有执行这组生成对照测试，未产生相关 API 费用。也未启用两个机器人互聊。如果以后启用互聊，应限制轮次与触发条件；人工延迟、碎片化消息或随机省略回复不是本轮优先方案。
