# 小c重连后补发

小c重新上线后，由原有两分钟健康巡检触发天气、新闻和金价的补发检查；快捷登录确认成功时也会立即触发，无需等下一次整点调度。后台工作进程运行固定入口，不调用模型或接受用户提供的命令、路径、账号。

- 天气：06:00之后补当天漏送的一条，允许恢复原先因08:25截止而标为过期的记录。优先使用当天已生成预报并标明生成时间；上午/晚间通勤时段已过时明确说明。没有当日缓存才重新采集。不补昨日天气，不重复发送已有回执或结果不明的记录。
- 新闻：先补仍有效、已生成的简报，再处理原队列中的其他到期内容，不重新采集或编辑。继续遵守原有免打扰、18小时有效期、每日预算和发送结果不确定时不重试的规则。
- 金价：用户选择“只补发仍有效的越界告警”。重连立即运行原金价检查，刷新报价后按原逻辑补发未送达的越界事件；回到区间则取消旧事件。已成功提醒的同侧持续越界不会重复发，过期行情不冒充当前行情。

三个入口共用各自现有文件锁、队列及回执去重。协调状态在 `/home/ubuntu/server-maintenance/recovery/.private/reconnect.sqlite3`，权限600；同一健康在线状态不会反复创建补发轮次。一个来源失败不阻塞另外两项，失败仅重试该项，最短间隔五分钟；已暂停的原定时器保持暂停。没有新增定时器，也不改变临时接待“不接新任务”的限制——这些是用户明确授权保留的既有后台通知。

`weather_catchup.py` 部署到天气目录，`news_recovery.py` 部署到新闻目录，`reconnect_push.py` 部署到聊天桥目录。`patch_reconnect.py` 给已有三个入口和快捷登录辅助脚本加小接缝，保留其他维护改动。上线需备份当前文件并核验差异。

验证：在Linux执行 `python3 -m unittest -v test_catchup test_reconnect_push`。部署验证还应对当前线上副本执行天气、新闻、金价的已有回归，并模拟“当天早报已过期后重连”和“简报待发送后重连”，确认仅一次投递。私密配置、数据库及回执留在服务私有目录，不纳入Git。
