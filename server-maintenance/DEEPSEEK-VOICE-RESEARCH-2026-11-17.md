# DeepSeek 语音接入与 token 节省调研

日期：2026-11-17，北京时间。性质：现有文件审查、历史巡检核对、官方文档调研；未部署、未重启服务、未调用付费接口、未发送 QQ 消息。

## 结论

DeepSeek 可以接入语音。对于现有 QQ 场景，优先复用小 C 的“QQ 原生转写 → 一次正常聊天生成 → 程序朗读回复”链路；本地 ASR 作为转写失败时的可选后备。网页端则优先评估 Harness 官方本地语音输入组件。单独部署轻量语音模型有技术可行性，但本次未取得服务器实时资源、安装版本和运行性能，尚不能视为已验证可部署。

语音模型本地化主要节省语音服务费和外部依赖；已经转成文字的同一句话，换成另一个 ASR 不会天然减少聊天 token。真正的节省来自减少模型请求次数、缩短重复上下文和不把音频/工具流水交给聊天模型。

## 已核实的现状

- 本地 `server-media/MEDIA.md`、`qq_media.py`、`tts_worker.py` 表明：小 C 接收 QQ `record`，用 NapCat `fetch_ptt_text(message_id)` 转写；Edge TTS 只接收回复正文，使用在线音色，不是服务器本地合成。
- 当前转写最多尝试两次；未识别时直接提示，不让模型猜测。语音开关由普通程序处理。超过 240 字的回复使用固定语音提示，未额外调用摘要模型。
- 维护目录记载 DeepSeek 已经通过 OneBot 插件接入 QQ 和 Harness。准确插件包名、版本及语音扩展点，本次未能在线读取，因此不能断言只开一个开关即可用。
- 历史聊天“服务器核心功能总控”的 2026-11-16 巡检记录：Ubuntu 24.04.4 LTS，总内存约 3.6 GiB，当时可用约 2.3 GiB，磁盘剩余约 25 GiB。它们是历史值，不代表今天实时余量。
- 本次两次获准的 SSH 检查均在握手阶段超时；没有获得远端命令结果。这不能单独证明服务器宕机或资源不足。首次沙箱内连接被网络权限阻止，随后切换获准的只读连接。

## 三条接入路线

| 路线 | 输入识别 | 回复朗读 | 适合当前情况 |
|---|---|---|---|
| 复用现有方案 | QQ 原生转写 | 现有 Edge TTS | 优先用于 QQ；新增资源需求小，但两端都依赖外部服务 |
| 本地或混合 | SenseVoiceSmall INT8；QQ 可先用原生转写 | Edge TTS 或本地中文 VITS | 希望降低外部依赖时分步评估 |
| DeepSeek 官方语音 API | 官方 ASR | 官方 TTS | 需要官方接口和独立语音计费时考虑；不默认切换现有额度路径 |

**网页与 QQ 要分开接线。** 官方 Harness 语音输入组件为网页麦克风服务；它的存在不意味着 QQ 的 `record` 已经自动接通。QQ 仍需从已安装 OneBot 插件的入站处理接转写，并在最终回复后的程序钩子发送音频。

## 本地模型选择

**ASR：首选评估 SenseVoiceSmall INT8 + sherpa-onnx。** Harness 官方仓库已经提供实验性、默认关闭的语音输入 bundle；识别 provider 在 CPU 子进程中运行，支持普通话、粤语、英语、日语、韩语，支持按空闲时间回收。INT8 权重约 239 MB，FP32 约 938 MB；运行内存高于权重文件大小，并随录音长度增长。不要把“239 MB 模型”写成“只需 239 MB 内存”。[官方 bundle](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/experimental/voice-input-bundle/README.md)、[官方 provider](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/experimental/speech-to-text-sensevoice/README.md)

基于历史约 4 GB 级服务器，低频、单用户、短语音、一次一个任务值得试验；尚无现场测试支持固定延迟或内存承诺。若 QQ 原生转写已经可靠，始终加载本地 ASR 未必有收益。

**TTS：先保留 Edge，离线备选测试中文 VITS。** sherpa-onnx 提供多个约 115–117 MB 的中文 VITS 和 163 MB 的 Melo 中英模型；实际内存、中文数字读法、音色与耗时需要对照试听。Melo 官方树莓派示例 RTF 约 2.5–6.7，说明“模型小”不保证生成快，不能直接推算腾讯云机器的性能。[模型和基准](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/vits.html)

Piper 中文 huayan 模型文件约 63.2 MB，但其模型卡把训练数据许可证标为 Unknown；不把它直接定为上线首选，待确认用途和权重来源后再评估。[文件](https://huggingface.co/rhasspy/piper-voices/tree/main/zh/zh_CN/huayan/medium)、[模型卡](https://huggingface.co/rhasspy/piper-voices/blob/main/zh/zh_CN/huayan/medium/MODEL_CARD)

当前不优先选择带大语言模型的语音对话、声音克隆或大规模 TTS 框架：这个单用户 QQ 任务只需要转写和朗读，先评估上述 CPU 路线即可。

## 节省 token 的具体办法

1. **音频停留在媒体层。** 模型只收到最终转写文本；不把 Base64、音频路径、逐段识别过程塞进上下文。按 message_id 缓存转写，避免重连造成重复生成。
2. **一份回复复用。** 正常模型回复供文字和 TTS 共用；朗读、音色、开关、失败提示由程序处理，不再让模型调用一次“语音工具”并回来解释结果。若现有插件只能靠工具发消息，应先适配发送钩子，不能直接关掉必要工具。
3. **减少重复历史。** 先统计当前每轮输入，再试“近期完整对话＋少量相关记忆”；旧记录保留在数据库，按需检索。上下文压缩不等于删除记忆。尽量沿用 Harness 已有压缩能力，避免每轮额外调用摘要模型。
4. **保留稳定提示前缀。** 角色、权限及稳定规则放在前面；当前时间、动态状态、检索结果靠后。官方缓存按前缀匹配，尽量避免每轮在开头插入新时间导致前缀变化。缓存降低计费成本，命中 token 仍是输入 token；缓存不是永久或必然命中。[官方缓存机制](https://api-docs.deepseek.com/guides/kv_cache/)
5. **普通命令零模型调用。** `/语音 开启/关闭/男声/女声`、状态查询、测试文案走程序。闲聊在兼容的情况下使用较低思考强度或非思考模式；复杂问题再提高，先做质量对照。
6. **不为朗读单独摘要。** 长文保留完整文字，使用已有固定语音提示；日常对话从第一次生成就要求简洁。合成缓存可按“规范化文本＋音色＋模型版本”复用；是否发送仍按原消息 ID 去重。

实际用量报表属于私密运行记录，仅保留在本机，不随源码提交。评估时应对照输入、缓存输入与输出的比例，先检查重复上下文；有限样本不能推断全天账单或其他会话的表现。

作为计算示例，把每轮重复输入从 3,000 减至 1,000 token，该项减少约 66.7%；不是本次实测节省率。上线前后应在相近聊天负载下对照每轮输入、缓存命中、输出、模型调用次数，以及识别失败率与回复质量。

## 官方语音 API 成本对照

截至本次查阅，官方 ASR 为整段音频识别，最长 120 秒、最大 8 MiB，不支持流式识别；限时价 $0.058/音频小时，标价 $0.116。官方 TTS 支持 HTTP 和 WebSocket，限时价 $0.225/万计费字符，标价 $0.45；一个汉字算两个计费字符。[ASR 文档与计费](https://api-docs.deepseek.com/guides/asr/)、[TTS 文档与计费](https://api-docs.deepseek.com/guides/tts/)

仅作量级示例：每天识别 10 分钟、朗读 500 个汉字，按 30 天且忽略其他字符，限时价约为 ASR $0.29 + TTS $0.675 = $0.965/月；按标价合计约 $1.93/月。未含聊天模型费用、其他字符、税费或汇率，也不代表当前账号已有 API 权限。优惠可能变化。

所以，为低频个人使用而升级或新租服务器，未必比语音 API 划算。现有 QQ 原生转写＋Edge 链路没有新增付费 API，本地化应以可靠性、隐私和可维护性为主要收益；在线服务不承诺永久免费。

## 建议的试验顺序与验收

1. 恢复只读 SSH，确认当前 CPU、MemAvailable、负载、磁盘、Harness 和 OneBot 插件版本，以及语音能力是否已存在。对照小 C 实际部署文件与本地副本，避免复制过期代码。
2. 先在独立测试目录验证 DeepSeek QQ 收件转写、同轮回复复用、音频编码与发送接口。不得把网页麦克风组件当成已完成 QQ 接入。正式接线前保留代码和配置备份。
3. 再按需试 SenseVoice INT8：初始单任务、1 个推理线程、最多 60 秒录音、空闲约 60 秒释放。这些是试验参数，不是官方默认值或已测性能。
4. 用非私人测试音频覆盖 5/15/60 秒普通话、安静/噪声、数字日期、静音；测冷启动、热启动、峰值 RSS、CPU、RTF（耗时/音频时长）、转写正确性和失败回退。上线目标可先定为短语音热转写 P95 < 3 秒、同时可用内存保留至少 1 GiB；不达标则维持原生识别，不硬挤资源。
5. 本地 TTS 独立测试 30/100/240 字和中英混读，对照 Edge 的音色、数字读法、生成时间和 QQ 实际可播放性。ASR/TTS 共用有界串行队列，避免多个模型同时抢占内存。
6. 确认重复消息只触发一次生成、语音发送失败不重发已成功文字、超时后回到文字可用。当前探索不擅自向真实 QQ 会话发测试消息。
7. 把模型调用计入既有 usage 账本；本地识别/合成记模型 token 为 0，但另记次数、耗时和失败数。远程语音按音频秒数/计费字符记录，不能伪装成零成本。

建议落点：**QQ 先复用小 C 媒体层；网页先检查官方 Voice Input；本地 SenseVoice 按需做后备；本地 TTS 暂列第二阶段。** 不因接入语音增加普通闲聊的模型轮次。
