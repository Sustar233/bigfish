# 为新的 QQ 角色启用聊天和生图

准备一个已登录的 NapCat 实例，使用独立的回环 OneBot HTTP 端口，并启用与现有实例相同的 `/_events` SSE 流。示例角色 `qinghe` 使用端口 `13301`。

1. 在服务器 `/home/ubuntu/qq-roles/qinghe/bridge/.private/config.json` 填写 `bot_qq`、`owner_qq`、`onebot_url` 和该账号的 `onebot_token`。示例 URL 为 `http://127.0.0.1:13301`。凭据文件权限设为 600。
2. 为改图和参考图接好该账号的附件缓存。目录为 `/home/ubuntu/qq-roles/qinghe/napcat-runtime`，其中 `qq-data` 和 `app/napcat/cache` 分别对应容器的 QQ 数据和 NapCat 缓存。
3. 在 `/home/ubuntu/server-maintenance/images/.private/accounts.json` 的 `accounts` 对象中，以新机器人的 QQ 号为键增加一项。

   ```json
   {"name":"青禾","role":"qinghe","model":"codex","port":13301}
   ```

4. 在画单空闲时重启 `qq-image-generation.service`。检查日志中的 `friend_stream_connected` 和角色名称，再用已添加的 QQ 好友私聊试画。主人也通过这个通用私聊入口使用新角色。每个账号只启用一个主动回复入口，避免重复发送。

`model` 可以选 `codex` 或 `deepseek`，用于普通对话。生图与改图统一使用现有图片服务。好友画单按机器人和发起人隔离。新角色的私聊情感记忆按角色和好友隔离。群聊、主人运维工具和聊天人设需要另行接入。

## 共用的聊天功能

- 在 `cards/<OneBot端口>.txt` 填角色的固定外观。可选同名 PNG 作为形象参考。比如青禾使用 `cards/13301.txt` 和 `cards/13301.png`。「画张你在窗边的照片」会使用当前角色的形象卡。
- 收到一组图后，说「第二张换成夜景，再给我两个版本」即可继续。也可以引用该角色过去 24 小时内在当前私聊发出的某张成图。时限只约束聊天引用，成品文件沿用原有保留设置。
- 「以后可以主动关心我」只开启当前好友与该角色的关系。可说「免打扰 22点到9点」或「以后不用主动关心我」。目前每段关系只跟进最近一件带明确日期的上台、演出、比赛、考试或见面。时间按北京时间。
- 可以说「上次我难过，其实是因为告别」「这件事以后别再提了」「把这段忘了」。后一项删除情感索引中的对应条目，原有 QQ 聊天记录遵循既有设置。
- 现有三人群可点名或 @ 指定发言者。群内看图取最近十分钟的群图，最多四张；图片说明仅用于本轮回复。
